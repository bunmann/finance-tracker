LESSON 1: FastAPI Basics
    REST API (Representational State Transfer Application Programming Interface):
    -> allows two systems to communicate over the web using HTTP

    HTTPS Methods (CRUD of WEB): GET = SELECT, POST = INSERT, PUT/PATCH = UPDATE, DELETE = DELETE

    RUNNING THE SERVER (Uvicorn):
    1. Navigate to folder
    2. Type in terminal:    source ../venv/bin/activate
                            uvicorn main:app --reload   
    -> main = filename (main.py)
    -> app = FastAPI variable instance inside main.py
    -> --reload = hot-reload server on code edits
    *** ALL APIS are in this venv: source ../venv/bin/activate

    INTERACTIVE DOCUMENTATION:
        URL: http://127.0.0.1:8000/docs (FastAPI Swagger UI)
        -> Auto-generated documentation for all routes
        -> Use the "Try it out" button to execute requests directly in browser

    BASIC ROUTE SYNTAX:
        @app.get("/")                    // Decorator: routes HTTP GET requests on path "/" to function
        def read_root():                 // Function: executes when route is hit
            return {"message": "hello"}  // Response: Python dicts are auto-serialized to JSON


LESSON 2: Pydantic Validation

    Pydantic: checks valid data type from user
    Errors: 422 - Wrong type
            200 - Good

    Path vs. Query Parameters:
    Path: Can send variable thru URL Path
    e.g. User types: /transactions/42
            @app.get("/transactions/{transaction_id}") 
            // transaction_id is sent variable we can use

    Query (After ? in URL): Used for filtering, sorting
    -> NOT appear in route decorator path 
    e.g. User types in address bar: /transactions?limit=10&type=expense
            @app.get("/transactions") 
            def list_transactions(limit: int = 10, type: str | None = None): // Takes user input 
            return {"limit": limit, "type": type} 

    Pydantic Schemas: Define JSON request/response templates using BaseModel

    @app.get(/path): reads and caches info
    @app.post(/path): receives and saves user data
    


LESSON 3 ORM & SQLALCHEMY:

    Object Relational Mapper (ORM): SQLAlchemy connects .py and .sql files
    -> translates database tables into Python classes, and database rows into Python objects
    -> SQLAlchemy SAVES and fetches data from DB

    Pydantic Schema vs SQLAlchemy Model: 
    -> Pydantic gatekeeps front to back end, is user input Validation
    -> SQLAlchemy translates between python and SQL database
    User sends JSON -> Pydantic Check -> SQL Database -> Python Backend


LESSON 4: Crud Endpoints:

User sends JSON  →  Pydantic validates  →  SQLAlchemy model created  →  Saved to PostgreSQL
                     (schemas.py)            (models.py)                 (database.py)

    Depends(get_db): auto opens and closes DB sessions

    DATABASE SESSION COMMANDS (SQLAlchemy `db`):
    * Write Operations (like git commiting):
      -> db.add(obj)     : Stages a new Python object/row to be inserted (like 'git add')
      -> db.delete(obj)  : Marks an existing database record to be deleted
      -> db.commit()     : Saves all staged changes permanently to PostgreSQL (like 'git commit')
      -> db.refresh(obj) : Reloads the object from the DB to fetch auto-generated fields (like IDs)

LESSON 5: Filtering and Pagination

  * Query/Read Operations:
      -> db.query(column1, colunm2, ...) : like SELECT, implict FROM is 1st mentioned TABLE
      -> .filter(...)    : WHERE
      -> .limit(N)       : LIMIT
      -> .offset(M)      : OFFSET
      -> .group_by()     : GROUP BY
      -> .join()         : INNER JOIN
      -> .first()        : Returns first result as python object 
      -> .all()          : Returns all results as a python list (of classes/models, or tuples of aggregates)
      -> .scalar()       : Returns the first column of the first row as scalar value
      -> .extract()      : Extracts a specific date part from a timestamp (e.g., month or year) inside .filter()


    Codes: 
    -> 2xx: Success
    -> 4xx: Client Error (e.g. bad data/type)
    -> 5xx: Server Error (e.g. Backend crashed/DB error)
