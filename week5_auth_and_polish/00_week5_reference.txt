LESSON 1: JWT Authentication — Backend

    Authentication: checking WHO you are
    Authorization: checking WHAT you can do

    JWT (JSON Web Token): industry standard for api authentication
    -> Flow: User sends email + pw -> Server verifies pw and forgets pw immediately -> Server creates and gives user Token (contains userID)
    -> User stores token -> User sends token with EVERY future request -> Server reads to know which user it is 
    ** Tokens are created using user ID (i.e. {"sub": "user_id"} is passed, sub for subject)
    ** Tokens can be reversed to only see User ID 

    Token looks like: header.payload.signature
    Header: algo + token type
    Payload: claims (data) + exp time
    Signature: signed with secret key -> proves token hasn't been tampered with
    e.g. eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxIiwiZXhwIjoxNzE5...

    Tokens are prefered over cookies:
    -> Self-contained, server doesn't need to store session data
    -> Works with any client, not only browser (mobile apps, Postman, etc.)
    -> Scales much better, since servers don't need to share session data

    To hash: use CryptoContext on bcrypt (slow on purpose, hard to decode)

    Concept | What It Does 
    **bcrypt** | Hashes passwords so they can't be reversed 
    **JWT** | Self-contained token carrying user identity
    **SECRET_KEY** | Server-side key used to sign/verify tokens
    **`Depends(get_current_user)`** | FastAPI dependency that extracts the user from the token
    **401 Unauthorized** | HTTP status code for "you're not logged in" or "bad token" 
    **HTTPBearer** | FastAPI helper that extracts `Authorization: Bearer <token>` headers 

        

LESSON 2: JWT Authentication — Frontend

    Flow: User opens app -> no token? -> Redirect to login -> Enters credentials 
          -> API validates -> Server returns token -> Store token in localStorage 
          -> Redirect to dashboard -> All future API calls have token auto sent

    Interceptor: middleware for HTTP requests, runs before every request
    -> For us: checks if localStorage has token and adds Authorization: Bearer <token> header if it does

    localStorage: Browser-provided key-value store that persists across page refreshes and browser restarts
    ->setItem(key, value) -> stores value
    ->getItem(key) -> reads value
    ->removeItem(key) -> deletes value

    useNavigate: React Router hook, lets you auto change pages in JS

    useState(!!var): converts var into a boolean (true if truthy, false if falsy)

    Routing now:
    -> If logged in: Gives between 3 choices of routes
    -> Not logged on: Swaps the choices out for other routes
    -> If user doesn't match any route: <Route path="*" element={<Navigate to="/login" />} /> redirects user to /login
    ** These are PROTECTED ROUTES **

    DOM (Document Object Model): Browser's internal map (tree) of all HTML elements on screen. JS/React updates this tree to refresh the screen.

    React Fragments (<> and </>): 
    -> Why: React requires every component to return only ONE parent element.
    -> Fix: Wrapping elements in `<>` and `</>` satisfies this rule.
    -> Key: They act as "ghost wrappers" — they bundle elements to satisfy React, but are NOT added to the DOM (so they won't mess up CSS layouts).


LESSON 3: CSV Import — Backend

    To avoid duplicate transactions we use SHA256 fingerprint hashing:
    -> Like pw hashing, but much faster and produces same unqie hash for each input
    -> For duplicaiton & identity purposes
    -> Takes in date + description + amount + # of occurrence (Needs EXACT description)
    -> Batch insert all non-duplicates at the end (accesses db only once, much faster than constant inserts)

    defaultdict(int): dict where any key defaults to 0, for counting occurance
    file: UploadFile = File(...): Way to get ANY file, from FastAPI
    -> file.filename.endswith(".csv"): to check file name
    -> io.StringIO: Wrap string to behave like file
    -> csv.DictReader: Parses csv into dict
    -> strptime to parse dates into date objects


LESSON 4: CSV Import — Frontend

    Getting file:
    -> accept=".csv": input attribute that restricts file selection in browser file picker
    -> e.g. <input type="file" accept=".csv" />
    
    Converting file to browser object:
    -> FormData: Browser object used to pack binary files (like CSVs) for HTTP uploads
    -> Acts like a container/box for raw file bytes

    Sending file to API:
    -> Content-Type: multipart/form-data: HTTP header that tells the backend how to parse the payload
    -> Tells FastAPI to use its file parser rather than its default JSON parser

    

LESSON 5: Budget Tracking

    POST vs PUT vs PATCH:
    -> Post is completely new resource
    -> Put is replacing existing resource w/ new entirely
    -> Patch is updating existing resource (only fields that you send)

    Promise.all: Does parallel API calls, and waits for all of them
    -> returns an array of results in the order they were passed in
    -> if one fails, goes to .catch

    value (controlled) vs defaultValue (uncontrolled):
    -> Controlled (value + onChange): React state is the source of truth (locked without onChange)
       - Best for: live validation, search-as-you-type, formatting inputs on keypress
    -> Uncontrolled (defaultValue + onBlur): Browser DOM manages the text dynamically
       - Best for: autosaving on focus out (prevents API spam on every keystroke), form performance
